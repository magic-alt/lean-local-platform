# 期权数据、研究与交易边界

本页说明如何在 LEAN Local 中检查期权合约、准备期权研究，以及在把研究扩展为回测或模拟交易前必须补齐的能力。当前平台已支持期权合约主数据、按需行情下载和质量校验，但**尚未把 `option` 接入 Project、Backtest 或 Paper 的正式资产类型**。因此 Data 页出现可交易合约不等于平台已经能够发送、撮合或行权期权订单。

## 当前支持范围

| 能力 | 当前状态 | 使用入口 |
| --- | --- | --- |
| 期权合约主数据 `opt_basic` | 支持，一键同步 | Data → 期权 Preview |
| 当前有效合约筛选 | 支持，按合约生命周期 fail closed | Data → 期权 Preview |
| 期权日行情 `opt_daily` | 支持按需下载，受 Provider 权限约束 | Data → 其他数据集 |
| 合约与日行情质量校验 | 支持 | Data 质量报告 |
| 期权因子、波动率或组合研究 | 可使用下载产物自行研究，尚无专用工作流 | Research / Jupyter |
| `assetClass=option` Project 和标准 Backtest | 不支持 | 不应绕过资产类型校验 |
| 期权 Paper、实时订单、保证金、行权与指派 | 不支持 | Paper 仅使用已准入的受支持资产回测 |

如果目标是可执行期权策略，应先完成本文最后的“接入验收清单”，再开放项目、回测或 Paper 入口。不能把股票或期货资产类型改名为期权来绕过门禁。

## 在 Data 页查看当前合约

先完成 `opt_basic` 同步，再打开 Data → 期权 Preview。页面只展示 Asia/Shanghai 当前日期处于以下闭区间内的合约：

```text
上市日期 <= 当前日期 <= 最后交易日期
```

结束日期优先使用 `last_ddate` 或 `last_trade_date`；数据源没有最后交易日时，依次使用 `last_edate`、`maturity_date`、`expiry_date` 或 `delist_date`。上市日或结束日缺失、格式无效、尚未上市或已经过期的合约都会被排除。最后交易日当天仍会显示。

这个筛选表示“合约生命周期当前有效”，不表示此刻一定可以成交。休市、临时停牌、无报价、涨跌停、流动性不足、账户权限和券商风控仍可能使合约不可交易。Preview 只读取本地归档，不会刷新实时行情。

## 关键字段

| 字段 | 含义 | 使用要点 |
| --- | --- | --- |
| `ts_code` | 唯一期权合约代码 | 行情、持仓和订单必须保存完整代码，不能只保存简称 |
| `opt_code` | 标的或期权品种代码 | 先核对它与策略标的是否一致 |
| `call_put` | `C` 认购 / `P` 认沽 | 决定权利方向和到期价值公式 |
| `exercise_price` | 行权价 \(K\) | 与标的价格一起决定实值、平值或虚值 |
| `s_month` | 合约月份 | 不能替代正式到期日 |
| `per_unit` / `opt_multiplier` | 合约乘数 | 权利金、盈亏、Delta 暴露和费用都要乘以该值 |
| `min_price_chg` | 最小价格变动 | 限价必须按 tick 对齐 |
| `list_date` | 上市日期 | 研究和回测不得在上市前选择该合约 |
| `last_ddate` | 最后交易日 | 新开仓、平仓和到期处理的主要边界 |
| `last_edate` / `maturity_date` | 最后行权日或到期日 | 不应默认与最后交易日相同 |
| `exchange` | 交易所 | 合约单位、行权方式、费用和保证金规则必须按交易所版本化 |

字段别名来自不同 Provider，使用前应查看实际下载结果。缺失乘数、最小变动价位、认购/认沽方向或生命周期的记录不能进入可执行合约池。

## 权利、义务与到期盈亏

认购期权多头到期价值为：

```text
max(标的到期价 - 行权价, 0) × 合约乘数 × 合约张数
```

认沽期权多头到期价值为：

```text
max(行权价 - 标的到期价, 0) × 合约乘数 × 合约张数
```

多头净盈亏还要减去建仓权利金和费用。买入时的基础现金占用为：

```text
期权价格 × 合约乘数 × 合约张数 + 费用
```

空头收到权利金但承担履约义务。裸卖认购的理论损失无上限，卖出认沽也可能产生显著标的敞口；保证金不能用“权利金 × 乘数”代替，必须实现交易所和券商对应的保证金模型。当前平台没有期权保证金、组合保证金或指派模型，因此不能把空头期权研究结果交给 Paper。

## 合约选择流程

每个研究日都应当按当日可见信息重建合约池，不能用今天仍活跃的合约回填历史：

1. 按交易所和 `opt_code` 选择正确标的。
2. 用 `list_date`、`last_ddate` 和到期字段删除未上市或已结束合约。
3. 选择认购或认沽方向，并根据标的当日价格计算相对行权价。
4. 计算剩余交易日，不要使用自然日直接替代交易日历。
5. 从同一交易日的 `opt_daily` 检查成交量、成交额、持仓量、买卖价或可获得的报价字段。
6. 对价格为零、OHLC 不一致、持仓量无效、行情日期错位或来源未认证的记录 fail closed。
7. 在信号记录中固化合约代码、选择日期、到期日、行权价、乘数、行情来源和选择理由。

“最近到期、最接近平值”只是筛选规则，不是流动性证明。研究至少应设置最小成交量或持仓量，并在没有可靠 bid/ask 时使用保守滑点，不能默认按收盘中间价无限成交。

## 回测必须处理的事件

完整的期权回测不能只把期权收盘价当作普通股票价格。至少需要：

- 合约上市、退市、到期和最后交易日；
- 标的与期权行情的时间对齐；
- 乘数、tick、费用、买卖价差、滑点和容量；
- 行权方式、自动行权阈值、现金或实物交割；
- 空头指派、保证金变化和强平；
- 标的分红、拆并股等公司行动引起的合约调整；
- 组合 Greeks 与到期集中度限制；
- 到期前主动平仓、移仓或允许到期的明确策略。

如果历史数据只有日线 OHLC，没有 bid/ask、隐含波动率或盘中行情，报告必须标注这些限制。不得用未来收盘价决定同一收盘成交，也不得在合约尚未上市时选择它。

## 风险检查

期权策略除普通仓位和回撤限制外，至少应限制：

- 单合约、单标的和单到期月份的最大权利金或保证金；
- Delta、Gamma、Vega、Theta 的总暴露；
- 临近到期和深度虚值合约占比；
- 最小成交量、持仓量和最大买卖价差；
- 裸卖、价差组合和未配对腿；
- 行权或指派后的标的持仓与现金缺口；
- 行情陈旧、交易所休市和合约元数据缺失。

多腿策略的原子成交不能从各腿日线收盘价推断。若执行模型不能表达部分成交、腿间滑点和保证金变化，应停止在研究阶段。

## 接入正式回测与 Paper 的验收清单

开放 `assetClass=option` 前，应同时完成：

1. 在资产领域、API Schema、前端类型和 LEAN 数据路径中正式注册 `option`。
2. 将 `opt_basic` 与 `opt_daily` 转换为 LEAN 可识别的合约、映射和行情文件，并验证时区与交易日历。
3. 增加期权链选择、标的订阅、合约生命周期和公司行动测试。
4. 实现费用、买卖价差、滑点、容量、保证金、行权、指派和交割模型。
5. 为多头、空头、多腿、到期、停牌、无报价和部分成交建立回归用例。
6. 让 preflight、Source Gate、结果解析、报告和 admission gate 识别期权专有风险。
7. 在 Paper 中保存不可变订单状态、保证金、行权/指派和标的交割 ledger，并通过重放幂等测试。

在这些项目全部通过前，期权 Preview 适用于合约发现和研究准备，不构成可执行交易能力，也不构成投资建议。

# 数据、增量更新与PIT

首次建库使用全量更新；成功完成后，一键按钮执行增量更新。核心行情、交易状态、复权、指数和日历数据以 MySQL 为事实来源，LEAN 缓存和 Parquet 是可重建派生物。

## 一键更新范围

一键更新只包含以下 10 个低频研究数据集：

- `stock_basic`、`trade_cal`
- `daily`、`adj_factor`、`suspend_d`、`stk_limit`
- `index_basic`、`index_daily`
- `fut_basic`、`opt_basic`

其他 catalog 数据集默认折叠并标记“按需获取，不参与一键更新”。需要时从单独操作启动，并从后台批准的宿主机目录中选择下载/导出目标，不会无提示地固定写入电脑默认硬盘位置。

50 GB 配置只限制按需写入 MySQL 的缓存；一键建库没有数据库容量上限，只遵守磁盘安全线：更新后必须至少保留 500 GiB 或总容量的 50%，取两者中更大的值。

## 正确性检查

- Provider 返回值先做字段标准化、主键去重和日期/数值校验。
- 行情检查 OHLC 关系、交易日、异常值和关键字段。
- 停牌、涨跌停和复权数据按来源优先级合并。
- 导入批次、数据水位、来源、质量报告和隔离行保留可追溯记录。

规范化表已经无损保存的数据不会再逐行序列化完整 JSON。系统只保留键、日期和哈希索引；不能无损规范化的原始响应按批 gzip 压缩并内容寻址归档。历史逐行 JSON 只能用维护脚本分段验证清理，不能直接清空 `provider_raw_records`。

## 数据集预览和 CSV

- 股票 Preview：资料、日线、复权、停牌和涨跌停历史。
- 交易日历 Preview：按市场和日期查看。
- 指数 Preview：指数资料和指数日线。
- 期货/期权 Preview：合约资料。
- CSV 导入前先下载对应模板；缺字段或类型错误会在入库前返回校验信息。

## PIT 股票池

独立批量回测默认取回测开始日的历史有效成分快照，并将解析后的股票代码固化到批次配置。动态组合按 `announce_date`、`effective_date`、`start_date` 和 `end_date` 在每个调仓日确定成分。缺少历史覆盖时应阻止运行，不能使用当前成分回填历史。

# Branding, Product Showcase, and Repository Discoverability

This document defines the maintained presentation and repository-identity surface for **LEAN Local Platform**. It covers real UI screenshots, the social-preview artwork, short demos, GitHub discovery metadata, and the `platform` → `lean-local-platform` repository migration.

The branding layer must never overstate the runtime boundary. The authoritative release state remains `NOT CERTIFIED`, and Live Trading / P9 activation remains disabled until an explicit architecture and certification effort changes that state.

## Canonical identity

| Surface | Canonical value |
| --- | --- |
| Project name | `LEAN Local Platform` |
| Repository | `magic-alt/lean-local-platform` |
| Short description | `Local-first QuantConnect LEAN platform for governed A-share data, reproducible backtesting, research artifact validation, optimization, and paper trading.` |
| Metadata source | `.github/repository-metadata.yml` |
| License | Apache-2.0 |

The repository slug is deliberately specific. `lean-local-platform` is materially easier to identify in links, GitHub Search, search engines, shell history, package documentation, and third-party references than the previous generic `platform` slug.

## Real UI screenshots

Do not use generated or hand-drawn mockups as product screenshots. The repository already has a reproducible Playwright screenshot pipeline using isolated E2E data.

From `web/frontend`:

```bash
npm run docs:screenshots
```

The screenshot generator writes tracked assets under `docs/help/assets/`:

- `data-library.png`;

The README should keep one strong primary image above the first long-form explanation rather than turning the top of the page into a gallery. Secondary screens are linked from the product-tour caption.

Screenshots are evidence of the user interface generated by the isolated demo environment. They are **not** evidence that the current release is certified or that live execution is enabled.

## 30–60 second demo

Record the demo from an isolated/sanitized instance, not from a mock UI and not from an account containing private credentials or production data.

Recommended 30–40 second storyboard:

1. **Data** — show the governed data library and dataset status.
2. **Projects** — open a strategy project and briefly show the editor/configuration surface.
3. **Backtests** — show the unified run configuration and preflight-oriented workflow.
4. **Optimization** — show experiment/optimization navigation without waiting for a long compute job.
5. **Reports** — show the audit/evidence-oriented output surface.
6. **Paper** — end on the paper-account surface; do not imply live broker writes are available.

Recording rules:

- 1280×720 or 1440×900 viewport;
- 30–60 seconds total;
- no real API keys, tokens, account numbers, broker credentials, private paths, or personal data;
- avoid fake PnL claims or cherry-picked performance headlines;
- keep the `NOT CERTIFIED` / live-disabled boundary intact in surrounding README text;
- prefer H.264 MP4 for a linked full-quality demo and an optimized GIF/WebP only when an inline README animation is genuinely useful.

A static screenshot should remain the default README hero because it is fast, accessible, diffable, and does not impose a large binary download on every visitor.

## GitHub Social Preview

Editable source:

- `docs/assets/lean-local-platform-social-preview.svg`

The composition is intentionally independent of transient strategy performance. It communicates the stable product identity:

```text
Governed Data → Research Artifact → LEAN Validation → Paper Execution
```

The artwork must not contain broker/live-trading imagery, fake performance numbers, or certification claims.

GitHub recommends PNG, JPG, or GIF under 1 MB, with 1280×640 providing the best display quality. Export the SVG source to a 1280×640 PNG, then upload it in the repository **Settings → Social preview** control.

Example export using ImageMagick when available:

```bash
magick -background none docs/assets/lean-local-platform-social-preview.svg \
  -resize 1280x640! docs/assets/lean-local-platform-social-preview.png
```

The exported PNG is a release/hosting asset; avoid committing repeated raster regenerations unless the repository intentionally decides to track the rendered file.

## Repository rename migration

The server-side repository name is now:

```text
magic-alt/lean-local-platform
```

The source tree must use the new slug for operational references even though GitHub may redirect old repository URLs.

### Operational references that must use the new slug

At minimum verify:

- README / README.zh-CN CI badges and clone commands;
- `.github/ISSUE_TEMPLATE/config.yml` security-policy URL;
- `.github/README.md` audit command;
- `docs/repository-governance.md` repository identity and audit command;
- `scripts/audit_repository_settings.py` fallback repository value;
- release/deployment scripts that contain explicit repository URLs;
- external CI, webhooks, local remotes, documentation sites, badges, and bookmarks maintained outside this repository.

Do not blindly rewrite `docs/history/` when an old path is part of immutable historical evidence. Rewrite historical content only when the old URL is being used as an operational instruction.

### Local clone migration

Maintainers with an existing clone should update the remote explicitly:

```bash
git remote set-url origin https://github.com/magic-alt/lean-local-platform.git
git remote -v
```

Optionally rename the local checkout directory for consistency; Git itself does not require the directory name to match the repository slug.

### Post-rename verification

Run:

```bash
python scripts/check_repository_hygiene.py
python scripts/check_developer_governance.py
python scripts/check_oss_governance.py
python scripts/audit_repository_settings.py --repository magic-alt/lean-local-platform
```

Also verify manually:

- repository homepage and README images;
- CI badge and Actions links;
- Security Policy link from the Issue chooser;
- release workflows and tags;
- GitHub About Description and Topics;
- branch/ruleset state;
- external integrations and webhooks.

## GitHub Search and external discovery

`.github/repository-metadata.yml` is the version-controlled desired state for the GitHub About description and Topics. Keep the server-side settings synchronized with it.

Discovery copy should consistently emphasize the terms that describe the actual project rather than broad generic tags: QuantConnect LEAN, quantitative finance, backtesting, paper trading, A-share, Tushare, reproducible research, FastAPI, React, PostgreSQL, RabbitMQ, Parquet, and DuckDB.

Avoid keyword stuffing in the README title or prose. The repository slug, concise description, focused Topics, real screenshot, recognizable Social Preview, and high-quality inbound links are more useful than repeating search terms unnaturally.

## Change policy

Update the branding assets when the project identity or primary workflow changes materially, not for routine UI polish. A visual change must never silently alter the documented runtime, data, security, or certification boundary.
